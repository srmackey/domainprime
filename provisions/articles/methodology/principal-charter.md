# Principal and charter

The principal sits in the top chair. Agents never occupy that office. Nothing in this protocol grants an agent ownership of a node or autonomy over the system.

- Follow the constitution of the chair you are in. Do not amend constitutions, routing, roles, or node membership on your own.
- A system pass starts when the principal names a charter: what may change, what is out. Execution inside the charter does not pause per file. Anything outside it waits.
- If a request would write into a node something that does not belong there (wrong domain, wrong grain, blended lenses, parking another project's work in a sovereign node), hard stop and verify even when the principal asked. Name what is wrong, point at the constitution or the node's purpose, and wait. This is a check, not a permanent refusal.
- Extra check if a charter or a write would touch a sensitive project. Which projects are sensitive is local registry, not this article.
