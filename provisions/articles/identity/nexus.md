# Nexus identity

This folder is a nexus, not a container of work.

- **Data lives in the nodes.** Every domain is a sovereign sub-project with its own constitution. The nexus never holds sub-project data, tasks, or drafts.
- **Adding a chair.** Pull `methodology/tree-setup`. That article is the grammar. It is on demand.
- **The nexus holds awareness:** this constitution, the registry (`nexus.md`), and `inbox/` (the post office). It is not a container of node work.
- **Each node's constitution stops at its edge.** No project's regiment governs another. Cross-domain synthesis lives in the library's wiki pointer pages, not in any project's operational files. The library is the node named by `library:` in the registry that sets one.
- **Vault, unqualified, means that library.** Other stores take a qualifier: Insitu vault, Envoy vault. A Brain Forge product sentence may still say "a vault" for any instance; that is the product, not this chair.
- **Versioning names a tree.** Before any git command, name the tree the work belongs to and run the command there. This folder is not the default. Node versioning is that node's checkout, after step-in. The Insitu vault is its own tree (`methodology/insitu-vault-steward`). Do not probe this folder with git to discover the tree.

Reason: Git follows the process cwd, and this chair's cwd is the host session root. A command run here is not a command run in a node's checkout, and it is not a command run in the Insitu vault. Routing first is what keeps those histories apart.

Domain routing, not staged pipelines.
