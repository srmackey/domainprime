# Tree setup

A nexus adds a chair by writing that chair's `AGENTS.md` and a row in its `nexus.md`. The file is the constitution. It names the chair's kind and what the chair is for.

## Kind

The top nexus is one per install. A line of work that carries its own standard is a nexus under its parent. A project is a node under the nexus it belongs to.

## Initialize

Insitu subscription is not part of creating the folder. On the first working session in that chair, ask what to subscribe and whether anything new has to be written for it. Subscribe only after that answer. The chair may keep its own constitution and never subscribe.

## A node that ships

A node meant to run somewhere else has three parts.

- **Checkout.** Where the code is written.
- **Sandbox.** Where it runs without a customer environment. The runner is chosen for the work. It can be changed, and the node may use more than one.
- **Release.** An install and config that put it on another machine.

The node has a goal and a benchmark. The line it sits under says how hard a claim is checked. A claim that was not measured is not stated.

Records of the install stay out of that node and out of its release: status, sittings, protocol, and roster files. A git repo starts when code lands. A remote is a later, intentional step.

## What an install does not copy

Another install's chairs, notes, and week are not part of setting up a tree. A child nexus's standard lives in that nexus's constitution. Adding a chair does not assume a named line or a named project.

Reason: a tree rule that names one install's folders will be copied into the next install as if those folders were the product. The grammar travels. The instance does not.
