# Settle

Settle reconciles this chair's records against what is true, fixes what it may fix without asking, and reports what it did. This article is the operation. What counts as settled on any given surface is not here.

**Settle names no system.** A chair's settle behaviour is whatever settle contracts its map composed, and a contract announces itself by being present in the composed protocol. A chair that composes none settles only the surfaces this article owns directly.

## Scope

One run covers, and covers only:

- every settle contract composed into this chair's protocol,
- any working surface this chair's own constitution names as its state, such as a native todo or focus file, at whatever grain that constitution sets,
- whatever this chair's Forefront points at,
- carry-backs held by this sitting. Only a sitting that arrived carrying another chair's lens can hold one, which in practice means a nexus sitting that stepped in here. A sitting bound to this chair holds none, because anything it cannot close leaves as a letter instead.

Always chair-scoped. Settle never reads another chair's records, never runs from one chair onto another, and the nexus never settles a node. Do not walk the tree for surfaces nothing named. A pass the principal names is `methodology/settle-pass`. That pass walks by stepping in. This article still governs each chair.

## Order

Contracts run in dependency order: **sources, then digests, then publications.** A contract declares its tier. Settle sorts on the tier and stays ignorant of which system it is sorting.

A source holds a durable original. A digest summarises sources. A publication is derived from a digest. Settling out of that order reconciles a digest against inputs that are about to change underneath it.

## The five tests

Generic across contracts. The contract says which surface, the test says what to look for. Run them across a surface's sections together, which is where duplication becomes visible.

| Test | Finding |
|---|---|
| Landed | The work is done according to a durable source. |
| Stale | The entry names a state that is no longer true: a moved path, a shipped version, a passed date. |
| Duplicate | The same item appears in two places. |
| Not this chair's | A line only another chair can close. |
| Orphan | The entry points at something that no longer exists. |

Which place wins a duplicate belongs to the contract, because that ranking names one system's internal structure. The board is the principal's and a settle run never edits it.

## Acting on a finding

Every finding runs `methodology/autonomy-gate-provenance`. What passes is settled and reported, never proposed. What fails resolves by promotion: give it a durable home, then settle it. Never by deletion, and never by a question. A not-this-chair's finding leaves as a carry-back or a letter, and is never resolved by deletion.

## Triggers

Sitting down in this chair, stepping in, stepping out, and on demand: `settle`, `status`, `update status`.

Never on a timer, and never because a session opened somewhere else. **A settle run never starts the work it reconciled.** Making the next move visible is not permission to take it.

## Report

    checked status

    * removed stale item x
    * removed stale item y
    * cleared envoy mail
    * added new inbox item to sitrep

Settled work, reported. Not a diff to approve. Anything that failed the gate and could not be promoted goes below that block, as the only part wanting the principal.

**Class: composition, opportunistic.** Settle acts on whatever contracts are present and degrades to nothing when there are none, so it assumes no system and requires none.

**Executable.** Skill `settle`.

Reason: a chair's surfaces are maintained by different systems, each of which can tell when its own surface is wrong and none of which can see the others. A pass owned by one system reconciles against a world the other systems are still changing, and a single pass that knew them all would need editing every time a system was added or removed. Separating the operation from the definitions is what lets a chair's behaviour follow its map with nothing to keep in sync.
