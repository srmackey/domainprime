# Settle pass

The principal names a scope. The argument is a nexus, or `all`.

`all` is this chair and every active chair under it. A nexus name is that nexus and every active chair under it. Superseded and parked rows stay out. A name this chair does not contain is refused.

The pass steps into each chair, parent before children, and runs settle there. `methodology/settle` still governs the chair: fix what the gate can prove, leave what it cannot, do not ask in the middle, and do not start the work.

## The report

One overlay file, `settle-wait.md`, on the chair that ran the pass. The next pass replaces the file. Nothing is appended.

An item names the chair, the surface, the line, and why it was left. A sensitive chair contributes its address and a count. The lines stay on that chair.

The principal clears an item by calling it resolved. An item whose line is no longer on that chair is resolved. A sensitive count clears when the principal says so, or when a later pass records a new count. When nothing remains, remove the file.

## Waiting

After the session-start pack, search this workspace for `settle-wait`. That search is this file only. If the file is there, drop what is resolved, remove the file when the list is empty, and otherwise present the items and wait. This is not the status pack. It fires whether or not status was asked for.

**Executable.** Skill `settle-pass`.

**Class: composition, dependent.** Names settle, step-in, and overlay. The vault does not enforce that declaration.

Relation to `methodology/settle`: that article is one chair. This one is the named walk.

Relation to `methodology/nexus-board`: the pack is on request. This file waits the way a session brief waits.

Reason: the residue has to outlive the sitting that found it, and it has to leave when the question is gone. A mail note clears when it is seen. A session brief is a different file. One report that is replaced or removed is the record.
